# JeffCrunch

JeffCrunch is the spreadsheet app of JeffOffice. JeffOffice is an independent project: JeffCrunch aims to work with Excel workbooks and the people who use them (compatibility and interoperability), and then to do more, and do it better. Its feature checklist is [features/jeffcrunch.md](features/jeffcrunch.md); this note is the design, the order it is built in, and how each step is measured.

## The decisions (October 22, 2026)

- **Our own calculation engine**, in C++ (`libs/base/calc`). A spreadsheet engine is not a part you call once: every cell read, edit, recalculation, and undo goes through it, so it has to own its storage, recalculate only what an edit changed, and share undo with the app. It also serves JeffWrite's fields, JeffBase, chart axes, and `TEXT()`. IronCalc, an open-source engine, is run once through the same yardstick when the yardstick exists, so the choice is scored rather than argued.
- **About 110 functions first.** In the public workbooks, the 50 most used functions cover 91% of the workbooks that use functions and the 100 most used cover 99%. A formula with a function JeffCrunch doesn't have yet keeps the result the file stored, and shows `#NAME?` only once something it depends on changes.
- **Macros are kept, never run.** A workbook's macro project is read, kept untouched, and saved back. Converting macros to a JeffOffice script (translated to JavaScript, reviewed by you, run only when you allow it) comes after the preview, as its own project.
- **Formats.** `.xlsx` is the default. The first release opens `.xls` (Excel 5 to 2003), `.ods`, and `.csv`; saving `.xls` and `.ods` follows once `.xlsx` is solid. Whatever JeffCrunch can't edit yet is kept and written back as it was.

## The preview bar

JeffCrunch ships as a preview when, on public workbooks never used for tuning, it meets every line below. Each is measured by a program, with no other spreadsheet involved: a workbook stores the last result of every formula, so recalculating every formula and comparing with what the file stored checks the engine against thousands of real answers.

| Measure | Preview bar |
|---|---|
| Opening | Every file opens with no crash or hang; 99% of undamaged files keep their own cell count |
| Recalculating every formula against its stored result (to 15 digits; text, true/false, and error kind exactly; volatile, external, and unsupported formulas listed apart) | 90% of formula workbooks match fully; 98% of formula cells match; each of the 50 most used functions matches 99% of the time |
| Function test files from the public LibreOffice test suite | All for the first 110 functions; 80% of the rest |
| Number formats, checked against stored `TEXT()`, `FIXED`, and `DOLLAR` results | 98% |
| Saving | No crashes; 99.5% of workbooks read back the same; 100% of parts JeffCrunch didn't touch written back identical |
| `.xls` | Every file opens; 98% of values equal those of the same workbook as `.xlsx` |
| Damaged and deliberately broken files, plus 5,000 generated mutations | No crash or hang within 4 GB and 120 seconds |
| Speed: a 100,000-row by 20-column sheet, and the largest public sheet (151 MB) | First screen under 1 and 3 seconds; painting under 8 ms for 95% of frames; an edit repainted within 16 ms for 99% of edits |

Version 1.0 raises the recalculation bar to 98% of workbooks and 99.9% of cells, and the function test files to 95%.

**The workbooks.** The public collections (business models from the Enron case, school and lab workbooks, and workbooks from government sites) are split in two by each workbook's own name, so that copies of one workbook stay together: a practice half for tuning, and a held-out half that is only ever scored, in totals. The LibreOffice and POI test files are never tuned on; they are used for crash and hang sweeps.

## The model

- `libs/base/calc`: values (number, text, true/false, error, empty, and arrays from the start), number formats and dates (both date systems), the formula tokenizer and parser to bytecode, the evaluator over an abstract cell source, the dependency graph, and the function registry. No GUI.
- `libs/office/sheet`: the workbook model (sparse cells in row blocks, shared strings, styles, merges, names, tables, and the parts kept as read), the `.xlsx` reader and writer, then `.xls` and `.ods`.
- `libs/shell/grid`: the grid view on a grid model. Row heights are a default plus overrides with running sums; only the cells in view are painted, from a cache of their display text.
- `apps/crunch`: the window, commands, undo, sort, filter, and pages for printing.

**Recalculation is incremental.** A cell lists the cells that depend on it; a range is kept as a range in an index per sheet, never expanded to its cells. An edit marks what depends on it and recalculates in order with an explicit stack (a running balance 100,000 rows deep would overflow the system's stack). Volatile functions (`NOW`, `RAND`, `INDIRECT`, `OFFSET`) are re-registered on each run. Recalculation runs on the main thread in short slices, so typing never waits, and Esc stops it. Loading, saving, AutoRecover, sorting, and CSV parsing run on worker threads from a snapshot. The arithmetic follows the format's established behavior, oddities included (February 29, 1900 exists; sums that should be zero come out as zero), because the results files store depend on it.

**Undo** keeps changes, not copies: a command records the cells, styles, sort order, or inserted rows it changed, and undo applies the inputs again and recalculates.

**Hostile files.** Every count, size, and depth a file controls is bounded, at least ten times above what real workbooks use, and formula nesting is limited. The package reader inflates a part only when it is read, and sheets are read by a streaming scanner, so one huge sheet never has to fit in memory at once.

## Waves

Each wave ends with its own gate: the tests, the layer check, and the yardstick numbers it moves.

1. **The yardstick and the readers it needs.** `jcrunchtool`, which runs a list of workbooks under memory and time limits and writes a table of results; the package reader inflating parts only when read; a streaming sheet reader with shared strings; and the first scores (opening, cell counts, the formulas' stored results read).
2. **Number formats.** The whole format language (sections and conditions, colors, text, fractions, elapsed time, both date systems, locales), checked against stored formatted results.
3. **Formulas.** The tokenizer, parser, and evaluator, the dependency graph, and the first 110 functions, scored by recalculating every formula.
4. **The grid and editing.** The window, the grid, selection, editing, undo, formatting, and saving `.xlsx`, scored for speed and for saving.
5. **Toward the preview.** `.xls` and `.ods` reading, printing, charts that follow their cells, and the remaining preview items in the checklist, then the hostile sweep and the held-out scores.

## Where it stands

Wave 1 is built: the readers and the yardstick, on the practice half of the public workbooks (8,371) and no further.

- **Opening.** `jcrunchtool scan` ran every practice workbook in a child process with 120 seconds and 4 GB: all 8,371 opened, none crashed or timed out, and none was read only in part. The slowest is the workbook of the 151 MB sheet (two sheets of 151 MB of XML and 14.8 million cells in all) at 22 seconds and 236 MB; every other workbook took under 4 seconds and 45 MB. The 730 files kept for crash and hang sweeps (LibreOffice and POI test files, damaged and hostile ones among them) gave 0 crashes and 0 hangs, 706 opened, 24 refused with a message (not a usable package).
- **Reading.** Cells, formula cells, and formula cells with a stored result were counted again by a separate program for 500 workbooks, and 477,554 cells of shared formulas (200 workbooks) were expanded again by a second implementation: no difference. Of 9,116,886 formula cells, every one has a result stored, so the recalculation score in wave 3 has an answer to check each formula against. The functions are in the table `jcrunchtool scan` writes; the top 25 are IF, SUM, VLOOKUP, INDEX, MONTH, YEAR, MATCH, MAX, ISNUMBER, FIND, AVERAGE, LEFT, WEEKDAY, AND, OFFSET, SQRT, OR, EXP, MIN, RAND, ABS, LN, SUMIF, HOUR, and ROUND.
- **Memory and limits.** A package keeps each part compressed until it is asked for (`Package::readLazy`), a part is inflated as it is read (`openPart` streams, so a part of any size costs no memory), and a sheet is read in pieces into 24-byte cells, so memory follows the cells and not the XML. Each limit a file controls is at least ten times the largest found in the practice workbooks, and is noted where it is set (`libs/office/sheet/sheetreader.h`): the largest part (2 GB, against 151 MB), everything a package may inflate over its life (4 GB, against 302 MB; a part asked for again and again is counted again), and what one sheet takes, counted at what each thing costs as measured against the memory the process held (2.2 GB, against 207 MB for the largest sheet). A sheet whose cells all carry text, or wait for a shared formula, is refused at the budget with the process near 1.9 GB.
- **Hostile files.** The XML a part holds is passed through a guard before the parser has it (`libs/office/office/xmlstream.h`): it must be UTF-8 (a parser reads UTF-16 as other bytes than a byte count does), well formed where parsers disagree, with no DOCTYPE, no element of more than 1,000 attributes, and no piece (a text, a tag with its attributes, a comment) of more than 1.6 MB, so the parser never holds more than that at once. A workbook whose sheets share a part is refused. These are tested with 200 MB texts, comments, and attributes, 40,000 attributes in UTF-16, and a workbook of 40 sheets that are one part.
- **Speed.** The parser (`QXmlStreamReader`) takes about three quarters of the time, and the whole reads about 18 MB of XML a second: a sheet of 151 MB takes about 9 seconds. The first-screen target of wave 4 is met by stopping the read after the first rows, which the reader allows.

For wave 3: the text of a shared formula for each of its cells is worked out when asked for, by moving its references; it costs about half a microsecond for each reference (measured on 50,829 formulas with 592,424 references), so asking for every formula of a sheet at the bound of 100 million characters takes about 4 seconds. The calculation should work from the master's parsed form and move references in it, not take the text of each cell.

Wave 2 is built: the number formats, in `libs/base/calc` (no GUI; the date code of wave 1 moved there too). Checked on the practice half and no further.

- **The engine** (`calc/numfmt.h`) turns a value and a format code into the text a person sees, the color to draw it in (a number of the 56-color palette, with its RGB), where a `*x` fill goes, and where each `_x` space is. It reads the whole language: up to four sections (positive, negative, zero, text) with the defaults when there are fewer, conditions (`[>100]`, `[<=-5]`), quoted and escaped text, `0 # ?`, the point, groups of three, a division by 1,000 for each comma after the digits, percent, scientific and engineering notation, fractions (up to nine places, fixed denominators), dates and times (`m` is minutes after `h` and before `s`; fractions of a second; `AM/PM` and `A/P`), elapsed `[h] [mm] [ss]`, both date systems (February 29, 1900 and day 0 are there), `[$text-LCID]` currency and locale codes, the system long date and time (`[$-F800]`, `[$-F400]`), `General`, and the built-in formats by id (0 to 49, and the East Asian ones 27 to 36 and 50 to 58). A value is rounded as the original does, from its 15 significant digits as decimal text, rounded once from the number's exact value and half up (2.675 is 2.68 with `0.00`; a value of 16 digits shows zeros after the 15th); time is rounded to the least unit the code shows and the day moves on. General is the 15 digits, in scientific notation from 1E+15 and under 0.0001; given the width of a column, it shows the most digits that fit. Month and day names follow the code's locale: English (every English locale), German, French, Spanish, Italian, Portuguese, and Dutch are known by name, any other locale gets English names, and separators of numbers never change with a locale. `formatTextFunction`, `formatFixed`, `formatDollar`, and `dateValueOf` (month first, year first, or with a month's name, and a time after it that is ignored) are the engine's side of `TEXT`, `FIXED`, `DOLLAR`, and `DATEVALUE`. Where the format does not say, these rules were chosen and are in `numfmt.h`: the system's long date or time (`[$-F800]`, `[$-x-sysdate]`) is the pattern written after it if there is one (a file stores the pattern the style had), else the United States' pattern; a section of text that comes last (`m/d/yy;@`) takes no numbers, so one section before it takes all, with a minus sign; a value that no section takes (`[>100]0.0` with 50) can't be shown; a fraction with no whole part is the best fraction of the whole number at every size.
- **Bounds.** A code of more than 4,096 characters (the format allows 255, 233 found), a fifth section, more than 255 places in a section, more than 16 brackets, a fraction of more than nine places, or a code with a quote, bracket, or escape never closed is not valid and its values show as General; no text is made of more than 32,767 characters (a cell holds that many); FIXED and DOLLAR take at most 127 decimals. These are tested with a code of a million characters, 100,000 semicolons, 1,000 brackets, a text repeated 4,000 times over 30,000 characters, and random strings of the characters a code is made of (6,000 in the suite and 360,000 in one long run: no crash, no loop, nothing past the bound).
- **The readers** now have the styles part (`Workbook::styles()`: the codes the file defines, and the format of each cell format, with the built-in ids resolved) and the defined names (`WorkbookInfo::definedNames`). Limits, at least ten times above the practice workbooks: 100,000 number formats (1,736 found), 1,000,000 cell formats (1,887), 4,000,000 characters of codes, 100,000 names (3,295), and 20,000,000 characters of names and what they stand for.
- **The yardstick** is `jcrunchtool formats`. A formula that is `TEXT(x, "code")`, `FIXED(x, n, no_commas)`, or `DOLLAR(x, n)` of a number or of one cell (of its sheet, another's by name, or a defined name for one cell), alone or joined with other text by `&` or `CONCATENATE` (cells and strings joined as they are), has the text a format should make of x stored beside it; each is a case, formatted here and compared with the stored text. In the 8,371 practice workbooks 238 formulas are such cases (in 25 workbooks: 235 of `TEXT`, 3 of `FIXED`, none of `DOLLAR`; 16 distinct pairs of function and code, 149 of them `TEXT` with `00`), and 238 match. That is fewer than the 500 the bar would like, because most of the 8,920 formulas that call `TEXT` are inside another function (`DATEVALUE`, `IF`, `UPPER`) or take a number that a formula works out, which waits for wave 3. So two more kinds of case are counted apart: `DATEVALUE(TEXT(x, "mm/dd/yy"))`, whose day number is stored (6,353, all match: the text reads back as the day it was), and a number joined to text with no call (65,910, all match: the text General makes, though 57,001 of them are zero and none is under 0.0001 or over 1E+15, so the switch to scientific notation is checked by tests and not by the files). The whole run takes 108 seconds. The 730 files kept for crash and hang sweeps gave 0 crashes and 0 hangs.
- **The codes cells use.** The 516 distinct number formats of the practice workbooks all parse. The most used, by cells with a value: `General` (21.5 million), `#,##0 ;[Red](#,##0)`, `_(* #,##0_);_(* \(#,##0\);_(* "-"??_);_(@_)`, `#,##0`, `_(* #,##0.00_);...`, `_("$"* #,##0.00_);...`, `0.00`, `m/d/yyyy`, `0%`, and `"$"#,##0_);[Red]\("$"#,##0\)`.

Known limits of the built-in ids: ids 59 to 81 (which systems of other languages assign) are General here, ids 27 to 36 and 50 to 58 (the East Asian date and time forms) print a Gregorian year where they mean an era, and ids 5 to 8, 42, and 44 (with a `$`) and 14 and 22 (`m/d/yyyy`) are the United States' forms, which another system shows in its own.

Not yet: the engine is not wired to a grid (wave 4 gives it the width of the column, and caches the text of the cells in view); `TEXT` codes written in another language's letters (the German `TT.MM.JJJJ`), eras and other calendars (`e`, `g`, `b`), `[DBNum]` numerals, and locale-specific separators; merged ranges, tables, and the parts a workbook keeps as read; `.xls` and `.ods`; ZIP64 packages, which every reader here refuses. The held-out half has not been scored (only the lead scores it, in totals).
