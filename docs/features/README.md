# JeffOffice feature lists

JeffOffice is an independent project. Each app aims to work with Office files and the people who use them (compatibility and interoperability), and then to do more, and do it better. Each app has a feature list: a checklist of features, everything people rely on so their Office documents open, look right, and keep working, and then more, grouped the way the app's ribbon is (File, then each ribbon tab, then what sits under the ribbon), so the work can be planned, tracked, and judged. A line starting `[x]` is a feature that works today, `[~]` is one that is partly there (the note says what is missing, or what could not be confirmed), and `[ ]` is one that is not there yet. For an app that is not built yet, `[x]` and `[~]` count what the shared parts of the suite already do for it. JeffWrite is built (a preview since version 0.9.0, October 19, 2026), so its boxes count what that version does. Every item also carries a tier: **1.0** for what must work before the app is called finished (for JeffPub, before the beta label comes off, and for JeffDeck, more than it takes to drop the Preview label, which the items marked "(needed to drop Preview)" and the old `.ppt` fidelity fixes decide), and **later** for what few documents use or what needs a piece the suite doesn't have yet; the lists for apps not built yet add **first release** for the first public build. All six lists share one skeleton, in this order: the title; an intro paragraph with the date of the last review; the legend; the tiers; How the tiers were chosen (where the evidence and how a count of documents is read are explained for that app); Beyond the original; File (backstage); one section for each ribbon tab (for JeffMail, Accounts and sign-in, then the Mail, Calendar, People, and Tasks modules); Contextual tabs; Shortcut menus (right-click); one or more Under the ribbon sections; Fidelity and testing; Safety and limits; File formats; Shared with other JeffOffice apps; Left out on purpose; Decided; and Open questions. The legend and the tiers read the same in all six.

The counts are tallies of each file's checklist lines (`[x]`, `[~]`, and `[ ]`), so they move whenever a list is edited.

## How the lists were ranked, and kept current

An item is ranked by how many real documents use it, where we have the counts. They come from our own collection (for example, 2,082 documents for JeffWrite, 1,481 workbooks for JeffCrunch, and 54 presentations for JeffDeck) and from public collections (U.S. government `.doc` files, and three public spreadsheet collections: business models from the Enron case, school and lab files, and files from government sites). Where a count is missing, the list says so and ranks by what someone moving from other office software needs on the first day, then what a full replacement needs. That is the case for JeffMail and JeffBase, which have no usage counts, and for JeffPub, whose 284 real publications have been used to measure fidelity but not yet to count features.

Each list says near its top when it was last reviewed. When a feature lands, change its box in that list and move the date, and update the counts in the table above, so that a list never claims more or less than the app does.

Which parts are built once and shared, where each lives, which app builds it first, and which apps use it: [shared.md](shared.md). Where an app's list disagrees with it, the map holds.
