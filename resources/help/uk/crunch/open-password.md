# Відкриття книг, захищених паролем

<!-- keywords: пароль, захист, зашифрований, шифрування, відкрити, заблокований, неправильний пароль, скасувати, xlsx, xls, ods, захист файлу, пароль за замовчуванням, приватний -->

Деякі книги захищено паролем під час збереження: без нього жодна програма не прочитає вміст файлу. Це відрізняється від команд **Захистити аркуш** і **Захистити книгу** (див. [Захист аркуша або книги](protect)), які лише забороняють зміни. Книгу, захищену паролем, не можна відкрити, поки не введено пароль. На цій сторінці описано, як відкрити таку книгу і як її створити.

## Відкриття книги

Відкрийте файл так само, як і будь-який інший: натисніть **{key:Open}**, виберіть його або перетягніть на вікно. JeffCrunch помічає, що файл захищено, і перед читанням запитує пароль:

1. Введіть пароль у поле з написом **Цей файл захищено паролем.** Символи відображаються крапками.
2. Натисніть **Відкрити**.

Якщо пароль неправильний, JeffCrunch повідомляє про це й запитує знову, скільки б разів ви не спробували. Щоб зупинити, натисніть **Скасувати**: нічого не відкривається, а вже відкриті книги залишаються без змін. Паролі розрізняються точно: враховуються великі літери, пробіли та діакритичні знаки.

JeffCrunch нікуди не записує пароль. Він зберігається в пам'яті, поки книгу відкрито, щоб команда **Зберегти** могла знову захистити файл, і стирається, коли ви закриваєте книгу. Наступного разу під час відкриття файлу програма запитає пароль знову.

## Які файли можна відкрити

- **Книги .xlsx і .xlsm**, захищені одним із двох способів, які оригінальна програма використовує з 2007 року: новішим (ключ 128, 192 або 256 бітів; JeffCrunch також перевіряє, що ніхто не змінив файл після захисту) і старішим (AES з ключем 128, 192 або 256 бітів).
- **Книги .xls**, захищені будь-яким із трьох способів цього формату: просте шифрування найстаріших файлів, 40-бітове шифрування та сильніше шифрування, що використовує системну службу ключів комп'ютера.
- **Електронні таблиці .ods**, захищені паролем, у всіх трьох способах, якими їх записували LibreOffice і OpenOffice: найновішому (LibreOffice 25 і новіші блокують весь файл 256-бітовим ключем, а ключ з пароля обчислюють методом, навмисно сповільненим і таким, що використовує багато пам'яті, тому відкриття такого файлу триває трохи довше), 256-бітовому способі попередніх версій і найстарішому способі.

Для старіших файлів .xls є обмеження щодо самого пароля. Просте шифрування найстаріших файлів використовує лише перші 15 символів пароля і може містити лише літери, цифри та знаки набору західноєвропейських символів (Latin-1): пароль з іншими літерами (наприклад, грецькими чи китайськими) там ніколи не визнається правильним. 40-бітове шифрування приймає будь-які літери, але лише перші 16 символів. JeffCrunch не записує файли .xls із паролем.

Деякі файли заблоковано паролем, який відомий усім, щоб їх могли відкрити всі, але випадково не змінили. JeffCrunch відкриває такі файли без запиту.

## Коли файл не вдається відкрити

- **«The password is not correct.»** Введений пароль не є тим, яким захищено файл. Спробуйте ще раз, уважно стежачи за великими літерами та пробілами. JeffCrunch не може відновити втрачений пароль.
- **«This file is protected in a way this program can't open.»** Файл заблоковано не паролем, а іншим способом (наприклад, ключем, збереженим у сертифікаті), або у формі, яку JeffCrunch не читає.
- **«This file's password protection asks for more memory or time than this program allows, so it is not opened.»** Файл, створений у LibreOffice 25 або новішому, задає, скільки пам'яті та часу потрібно для перевірки пароля. JeffCrunch приймає не більше ніж у десять разів від значень, які задає сам LibreOffice (640 МіБ пам'яті), щоб файл, створений для виснаження ресурсів комп'ютера, не можна було використати. Файл, записаний самим LibreOffice, значно нижче цієї межі.
- **«The file is damaged, or it was changed after it was protected.»** Пароль правильний, але вміст файлу не відповідає тому, що було захищено: його обрізано, пошкоджено або змінено іншою програмою. Скопіюйте файл заново з оригіналу.

## Збереження з паролем

Натисніть **Файл**, потім **Захистити паролем** (або **Рецензування > Захистити паролем**), двічі введіть пароль і натисніть **Захистити**. Книгу буде записано із захистом під час наступного збереження: щоб відкрити файл, потрібно буде ввести пароль. Щоб змінити пароль, виберіть ту саму команду й введіть новий; щоб вилучити його, натисніть **Видалити пароль** і збережіть книгу.

Книга, відкрита з паролем, зберігає його, поки її відкрито, тож команда **Зберегти** записує файл знову з тим самим захистом. JeffCrunch тримає пароль у пам'яті лише до закриття книги, після чого стирає його. Файл, відкритий з паролем, не залишиться незахищеним випадково: якщо ви зберігаєте копію у форматі .xls або .ods, який JeffCrunch не може захистити, програма спершу попередить, що копію буде збережено без захисту, і ви зможете скасувати дію.

Використовуйте довгий пароль і зберігайте його в надійному місці: без пароля файл не відкриє ніхто, зокрема й ми.
